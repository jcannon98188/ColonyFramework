## Destination

An architecture spec for Colony Framework, ready to hand off for implementation tickets: module boundaries, the hard technical decisions (ECS, memory, scheduling, world/Fields, GPU Backend, determinism, save/load, Plugin model) and prototype evidence behind them. The map plans only; building happens in later efforts from the spec.

## Notes

- Colony Framework: modern C# framework for DF/RimWorld-style games using ECS, advanced memory management, GPU-accelerated simulation, procedural generation and cutting-edge .NET (Vector<T> etc.). Not a game; Game authors build games on it. See `GLOSSARY.md`.
- Target: .NET 11 RC (SDK 11.0.100-rc.2 installed), open-source NuGet packages, .NET 11 only, Native AOT-friendly where possible, not Unity-compatible.
- Scope in: simulation core (ECS, scheduler, memory, save/load, determinism), colony-sim building blocks (pathfinding, jobs/AI, needs, Fields), procedural generation, extension points for modding and scripting. Out: rendering, input, audio, UI (headless).
- Modding/scripting are first class but unopinionated: the Framework defines extension points, not a scripting language or mod format.
- Platforms: Windows and Linux required, macOS nice to have. Dev GPU: NVIDIA RTX 2060 SUPER.
- GPU: dropped from v1 (CPU-only); earlier GPU Backend work is retained as research for a later optional package (wgpu-native, WebGPU/wasm not a target).
- Determinism: CPU simulation is deterministic.
- Scale target: 100k+ Entities, World around 512x512x256 tiles.
- ECS: build from scratch; survey Arch, Friflo and others for lessons.
- World: Fields are first-class chunked grids with configurable depth (depth 1 = 2D); tiles are not Entities.
- Time: fixed-timestep Ticks only; per-system tick rates; parallelism from dependency analysis; rendering interpolation is the Game author's job.
- Memory: unmanaged hot paths, `unsafe` allowed inside the Framework, Components are `unmanaged` structs (no strings/references; use interned IDs/handles), no GC allocations per Tick.
- Priorities (order): ECS core and scheduler, memory and chunked storage, spatial indexing, save/load, pathfinding, jobs/AI, GPU Fields, Plugin architecture, procedural generation, profiling/debug tooling.
- Prototypes are throwaway, headless benchmarks (not a sample game): ECS storage + scheduler, and one GPU Field.
- Prototype tickets (and any POC/sample code) must be built by an Opus 5.5 agent (`claude-opus-5-5`); spawn the subagent with that model.
- Tracker: Backlog.md. Child tickets are subtasks of this map; blocking is `dependencies`; claim = assignee; resolved = status Done with the answer in the final summary.

## Decisions so far

<!-- the index: one line per closed ticket -->

- [Survey existing ECS designs](TASK-1.1): archetype/table storage dominates, sparse-set is the alternative; all parallel designs defer structural change through command buffers; relationships can fragment archetypes; command-buffer merge order vs determinism unsettled. Detail in docs/research/ecs-designs.md.
- [Survey GPU compute options from .NET](TASK-1.2): NVRHI is D3D11/D3D12/Vulkan with no macOS, no C API and no C# bindings (highest effort); wgpu-native has the best coverage; no option covers every platform plus unmanaged-memory interop plus Native AOT, so use a Backend abstraction with explicit upload/readback. Detail in docs/research/gpu-compute-options.md.
- [Survey .NET 11 performance features](TASK-1.3): stable vs RC2 vs preview feature map; prefer fixed-width VectorNNN<T>, aligned NativeMemory; saturating float conversions and lane-reduction order are determinism hazards; runtime plugin loading conflicts with Native AOT. Detail in docs/research/dotnet-11-performance-features.md.
- [Decide Entity and Component data model](TASK-1.5): archetype/chunk SoA base with opt-in non-fragmenting Components; 64-bit stable Entity IDs; frequent states as enable bits/data; EntityId reference fields plus a non-fragmenting relation index; deterministic per-System command buffers; source-generated typed queries; buffer Components; stable Component names + layout hash; first-class Resources.
- [Decide memory model](TASK-1.6): 64 KiB chunks with CPU-independent 64-byte aligned layout; slab allocator plus per-Tick scratch arena with a World budget; debug-build ref validation and leak checks; inline-then-overflow buffer Components; interned strings and immutable blob store; zero-allocation Ticks enforced by tests; unsafe confined to core internals; SIMD float policy deferred to the determinism ticket.
- [Decide scheduler, tick model and parallelism](TASK-1.7): source-generated Systems with declared access; fixed Phases with stable deterministic ordering; own work-stealing pool across Systems and chunks; per-System rates with offsets and chunk skipping; host owns the loop (TickClock helper); chunk-partitioned writes plus ordered reductions, verified by 1-vs-N-thread hash comparison; typed event queues as Resources; deferred-completion Systems for cross-Tick work.
- [Decide World, Field and spatial indexing design](TASK-1.8): bounded World in v1 with chunk table, ChunkProvider and pure generation designed for later streaming; 16x16x16 row-major Field chunks iterated in Morton order, uniform chunks; Fields as named single-cell-type grids; double-buffered or colour-ordered in-place stencils; Entities with TilePos vs tile Fields; incremental chunk-bucket spatial index with deterministic result order; per-chunk change feed; CPU/GPU authority per Field.
- [Decide GPU Backend abstraction and first Backend](TASK-1.9): SUPERSEDED FOR v1 (CPU-only; retained as the design for a later optional GPU package). Original gist: compute-only Backend interface (Device/Buffer/Kernel/Command batch/Fence/capabilities) in separate packages; WGSL kernels compiled at build time, each with a CPU SIMD reference; wgpu-native first with our own generated bindings (NVRHI dropped); explicit dirty-chunk upload/readback via staging ring; fixed-latency deferred completion; kernels declared Exact or Approximate; always-available CPU Backend; CPU-mirror recovery on device loss; renderer reads Fields from CPU in v1.
- [Decide determinism contract](TASK-1.10): Tier 1 bit-identical across threads, CPU widths and Windows/Linux x86-64 for the same build, Plugins, seed and inputs (ARM64/macOS best effort); Framework math layer with fixed SIMD width and own transcendentals; fixed-point types; counter-based RNG; analyzer-banned nondeterminism sources; Deterministic/NonDeterministic Plugins; World hash from ordered chunk hashes; replays and saves bit-exact when fully deterministic; Approximate GPU Fields reads mark the World non-deterministic.
- [Decide save/load and versioning](TASK-1.11): snapshot of canonical little-endian chunk memory in a single sectioned container (manifest, schema table, per-chunk sections, checksums, World hash verified on load); rebuildable state not saved; explicit per-Component migrations; Plugin set recorded; per-section LZ4/Zstd; Tick-boundary saves with optional copy-on-write background mode and delta saves; managed Plugin state via registered callbacks; atomic write with backup generations; host-side Save/Load API building a fresh World.
- [Decide Plugin and extension architecture](TASK-1.12): two extension surfaces only: the C# API (Game authors and libraries; Plugin manifest with one Register entry point, dependency/ordering/conflict rules, Overridable Systems, Definition registry with patching) and a versioned in-process C ABI for Modders and script hosts (works under Native AOT, DFHack-style); no sandbox; scripting is a Plugin hosting a runtime over one handle-based bindings surface; no runtime C# assembly loading in the core; separate C# API and C ABI versions.
- [Decide testing and benchmark strategy](TASK-1.16): six test layers; shippable determinism harness (thread/ISA/AOT matrix, negative control, committed golden hashes, save-load equivalence); all-thread allocation harness plus debug memory validation; generator snapshot, analyzer and C ABI conformance tests with checked-in header diff; BenchmarkDotNet plus a custom Tick harness with JSON results; track-not-gate performance with hard gates only on deterministic counts; Windows/Linux PR matrix with nightly AOT/ISA/ARM64/soak; model-based tests against slow reference implementations; CPU-oracle Backend parity suite; seeded test content and golden saves.
- [Decide profiling and diagnostics](TASK-1.18): fixed always-on numeric counters in a preallocated per-Tick record ring; Off/Standard/Detailed cost levels (Standard under ~1% via per-System-per-worker timestamps); allocation-free read API with EventSource/Meter, Perfetto trace and protocol sinks; first-class all-thread allocation check; optional Tick budget with slow-Tick reports; structured allocation-free logging; flag-controlled validation switches; optional hash trail for divergence finding; Backend timing hooks; Plugin-registered counters.
- [Decide debug and inspection tooling](TASK-1.19): one versioned inspection protocol (binary plus JSON mapping) served in-process or over localhost socket/pipe; host-started, off by default, compiled out under COLONY_NO_INSPECT, token plus read-only default; reads at Tick boundaries; mutation only as recorded debug commands through the command buffer; pause/step and replay-based rewind; hash-trail desync finder and World/save diff; data-not-pixels visualisation; colony-inspect CLI as reference client (no GUI); Plugin-registered inspectors.
- [Decide procedural generation architecture](TASK-1.23): generation is a pure function of seed and chunk coordinate through ChunkProvider; named stages ordered before/after by name; counter-based RNG per stage and coordinate; region-keyed features, halo reads and a world-level pre-pass for global solves; Entity IDs derived from seed and placement; CPU baseline with optional Exact GPU stages; order-independence, seam and connectivity tests; integer/fixed-point noise ships, graph toolkit and WFC helper optional; generation version in the manifest.
- [Survey procedural generation approaches for colony sims](TASK-1.21): position-pure generation keyed to seed and coordinates is the cleanest design (Factorio, Minecraft); large features keyed to coarse regions; cross-chunk order dependence is the main determinism pitfall (use halo-based decoration); WFC fits poorly; data-driven name-based extensibility. Detail in docs/research/procgen-approaches.md.
- [Decide job assignment and colony AI building blocks](TASK-1.22): building blocks, not a blessed model; Claim Relation with two-phase propose/deterministic resolve; index of work (per-type per-chunk available lists) not agents; optional supply/demand hauling matcher; woken-not-polled decisions with budgets; anti-thrash defaults; optional priority-table and utility helpers (no BT/GOAP in v1); needs three reachability/cost/path-request queries from the pathfinding decision; needs and job content left to Game authors.
- [Survey job assignment and colony AI approaches](TASK-1.20): shipped colony sims use pull-based assignment with lexicographic priority then distance; claiming is separate from choosing (reserve at job start, abort and rescan on failure); thrash controlled by commitment and circuit breakers; scan cost dominates; GOAP/HTN fit mass agents poorly. Detail in docs/research/colony-ai-and-jobs.md.
- [Decide input and command ingestion, and the replay log](TASK-1.24): typed schema-registered Input Commands submitted from any thread with an effective Tick; canonical input list sorted by (Tick, source ID, sequence) applied in an Input Phase by handler Systems; deterministic rejection events; replay log = start state plus inputs plus checkpoint hashes in the save container format, with record/playback/seek/fork; lockstep-networking enablers (wire form, Tick gate, hash exchange, join via save plus log) without implementing networking.
- [Assemble the architecture spec](TASK-1.27): the destination reached: docs/spec/architecture.md assembles all decisions into a CPU-only v1 spec with Phase order, package map, hello-colony sketch and ordered implementation hand-off.
- [Decide package and assembly layout and public API shape](TASK-1.17): twelve lockstep-versioned packages (single Core for ECS, memory and scheduler; Fields, Persistence, Pathfinding, Colony, ProcGen, Plugins, Diagnostics, Generators, Testing, Abstractions, Native) with strict layering and a CI dependency check; safe public API with unsafe internal plus an Experimental Colony.Unsafe namespace; WorldBuilder composition root producing an immutable WorldSchema, no singletons; AOT-compatible and trimmable everywhere except the optional managed Plugin loader; C ABI as an AOT shared library with checked-in header; one solution with tests per layer; license and hosting deferred.
- [Decide streaming worlds](TASK-1.26): v1 ships seams plus a basic residency manager (Active/Hibernating/Unloaded, changes only in a Streaming Phase, focus points as Input Commands); chunk-owned Entities with a pinned global store; opt-in deterministic catch-up (frozen by default); halo ring of Hibernating chunks; unloaded chunk = its save section, plus a pathfinding summary with a deterministic "needs loading" result; async loads applied after a fixed N-Tick delay (stall if late); budgeted deterministic eviction; unbounded Worlds out of v1.
- [Decide pathfinding at scale](TASK-1.25): building block with region IDs, two-level chunk-graph HPA*, bounded lazily built flow Fields under a memory budget, and the three jobs queries plus a next-step query; Game-defined movement classes (per-World limit, default 32, ceiling 256) with lazy per-class structures; layered repair (dirty marking, lazy on read, per-Tick work budget, rebuild-vs-repair threshold); canonical request queue with work-unit budgets and fixed-delay results; incremental upkeep from the change feed; Tier 1 deterministic; GPU, navmesh, steering and collision out of v1.
- [Prototype GPU pathfinding for many units](TASK-1.15): GPU shared-goal flow Fields win only about 2x (7-9 ms vs 12-17 ms at 100k units) and per-unit GPU queries lose 17-20x to CPU HPA*; Field repair, not unit movement, is the cost; CPU region IDs mandatory; GPU and CPU results bit-identical; full-World Fields break at 512x512x64. **Decision: GPU is dropped from v1** (CPU-only; Field interface with CPU oracle kept as the seam; GPU becomes a later separate package), superseding the GPU Backend decision as a v1 deliverable. Default pathfinding: region IDs, chunk-graph HPA* with request budget, CPU flow Fields for shared goals. Detail in docs/research/prototype-gpu-pathfinding.md.
- [Prototype a GPU Field](TASK-1.14): GPU-authoritative dense Field wins about 15x (2.1 ms vs 32 ms) but a CPU-authoritative mirror never wins (PCIe-bound); small and sparse Worlds don't need the GPU; integer Kernel bit-identical on Vulkan and DX12, float differs up to 5 ULP. Amendments to the GPU Backend decision: mirror pattern dropped (CPU-only or GPU-authoritative Fields, checkpoint recovery), CPU default with explicit per-Field GPU opt-in, transfer budgets, staging ring plus scatter Kernel, Vulkan default, adapter limits, Exact-only on GPU in deterministic Worlds, own generated bindings. GPU-in-v1 still open pending pathfinding. Detail in docs/research/prototype-gpu-field.md.
- [Prototype ECS storage and scheduler benchmark](TASK-1.13): decided design hits the targets (100k colonists 1.02 ms single-thread, 0.20 ms on 12; zero allocation; bit-identical across threads and JIT/AOT). Amendments to the scheduler, memory and data-model decisions: default workers = physical cores with allocation-free parking; chunk-to-worker affinity; enable bits as the standard for frequent state; bulk command playback and deferred Entity handles; first-in-stable-order conflict rule for contested Entities; Vector128 fallbacks plus AOT x86-64-v3; keep waves. Detail in docs/research/prototype-ecs-bench.md.
- [Survey colony-sim hard problems in prior art](TASK-1.4): region/connected-component IDs fix unreachable-path freezes; DF fluids are a cellular automaton with a static flag; Factorio active-set scheduling for idle entities; job assignment and save/load sources are thin. Detail in docs/research/colony-sim-prior-art.md.
